# КТ2 — аналитический этап

Основа КТ2 — процесс из [описания КТ1](../business_process.md): от поступления заполненного обращения до доведения решения заявителю либо закрытия отозванной заявки. Договор, выдача денег и обслуживание задолженности за пределами модели.

Для группы ИКБО-10 процедурная версия выполняется **на Python**. Объектно-ориентированная версия на Java относится к КТ3. На КТ2 не подключается база данных: данные прототипа хранятся в стандартных структурах Python.

## Связь материалов

1. BPMN показывает участников, проверки, ветвления и передаваемые документы.
2. Таблица автоматизируемых операций связывает задачи BPMN с функциями Python.
3. Логическая модель данных описывает объекты, с которыми работают эти задачи.
4. Два алгоритма реализуют операции таблицы; их блок-схемы должны совпадать с кодом.
5. Отчёт КТ1 дополняется аналитическим разделом и рисунками моделей.

Рабочее обоснование операций, сущностей и алгоритмов — в [analysis.md](analysis.md). Исходный код и инструкция запуска — в `src/`.

## Что требуется к сдаче 3 ноября 2026 года

- BPMN 2.0 с пулами и дорожками, событием начала и завершения, шлюзом и объектами данных; исходник и PNG.
- Таблица минимум трёх автоматизируемых операций с точным совпадением названий задач BPMN и функций Python.
- Логическая ER-модель минимум пяти связанных сущностей; связь M:N через ассоциативную сущность, ключи, мощности и обоснование 3НФ; исходник и PNG.
- Два связанных с процессом алгоритма разной сложности; у одного ветвление и вложенный цикл; для каждого исходник и PNG блок-схемы по ГОСТ 19.701-90.
- Процедурная программа на Python, пример входа и результата, воспроизводимая инструкция запуска.
- Один ZIP с `report.docx`, `models/`, `src/`, `vcs/git_log.txt` и `vcs/repo_url.txt` в точной структуре памятки.
- Не меньше трёх новых коммитов после КТ1, сделанных в разные реальные дни.
